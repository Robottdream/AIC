# 圆形全向车贴墙角进门卡住修复（2026-10-03）

后续从另一接近路线再次出现弦线切弯，已增加沿路径前瞻与控制前缀偏离约束，并完成原三红A抓放队列，详见 `docs/path-following-fix-20261003.md`。下文记录本次前一阶段，不能代表后续控制器最终版本。

现场根因包含两个部分：导航允许的贴墙距离小于停车保护边界；DWB在±1m/s速度范围内只有11档采样，低速候选不足，到点附近容易把停止选为最低代价。

## 现场证据

车辆卡在 `(2.891,-1.921)`，左右雷达变换到车体中心后的最近距离分别0.3861/0.3868m；原0.405m NearStop内分别有36/48个点。原导航半径0.325m，加默认padding后约0.339m，允许到达这片区域，但碰撞监控已全方向停车。地图栅格量化也使规划距离与实际雷达距离存在几厘米偏差。Humble入圈时检查当前点，因此改成同一大足印的approach也不能自动脱困，参见[Nav2 Polygon实现](https://github.com/ros-navigation/navigation2/blob/humble/nav2_collision_monitor/src/polygon.cpp)。

到点失败的真实DWB评价另外显示：停止总代价5.855；(-0.2,-0.2)候选总代价6.633，目标代价下降但终点越过路径，路径代价增加。预测没有拒绝这些候选，Oscillation也没有拒绝。单降低障碍权重或增加到21档仍在约0.15m处停止，因此不能归因于雷达预判丢失，也不能只靠提高移速解决。

## 最终改动

- 两套新车型导航足印半径改为0.450m，加0.010m padding，包络在0.405m停车圈外留出栅格/测距余量；这是导航安全余量，实体模型尺寸未改。
- 局部/全局膨胀半径1.0m、cost_scaling_factor=2.0，ObstacleFootprint.scale=0.05，让规划提前离开墙角。1m/s合速度、0.7m/s²轴加速度、6m局部地图保持。
- Collision Monitor的NearStop恢复并维持原0.405m圈；2s碰撞预测改用 `/navigation/collision_footprint` 实体0.325m足印，避免把扩大后的导航安全余量重复算成实体尺寸。最终保护负责发布24点足印；旧车型参数默认0，不改变旧接口。
- 新 `FineOmniTrajectoryGenerator` 继承原StandardTrajectoryGenerator的加减速/制动模拟，保留原11×11全速度采样，并补充±0.075m/s范围内、间隔0.025m/s的48个低速候选。候选遵守当前轴限值、合速度限值和最小速度限值。没有把整个网格一直扩大到41×41；21×21中间版曾增加控制循环负担，已收回。
- 用户要求的已知场景轨迹预测保留：4s全局软代价、1.8s DWB逐时刻预测、最终雷达碰撞与数据失联停车。

新增依赖仅为机器已安装的dwb_plugins，未安装新软件或重依赖。选择性构建bot_navigation通过，当前新副本已启用；原 `/home/polarbear/ws_aic` 源码未覆盖。

## 当前脱困与验证范围

为从已经进入停车圈的位置恢复，先验证观测点沿0.7m向前、0.25m横移的扫掠距离始终≥0.386m，再临时采用0.360m停车圈、0.12m/s合速度，保留原实体足印2s碰撞预测、真实双雷达与最终失联保护。10.95s退让成功，峰值0.120m/s；完成后恢复0.405m圈，最终通行脚本显式读取参数确认原圈已恢复。不是关闭碰撞监控后强行穿墙。

实体0.325m足印不能表示机械臂和所携物块的完整三维包络，仍沿用前轮模型的局限。原三红A任务早已失败且可能仍携带red_cube_4，本轮只导航，未发抓取、放置或新业务任务。

真实NavFn隔离1.3m门洞测试，新旧路线都成功，最小中心到墙距离均0.650m；新版路径4.649→4.939m。这只能证明加安全余量后仍可通行，不能说这个测试的最小间距提高了。

真实DWB隔离测试覆盖横穿、迎面、已知折返、远离、过期与近目标低速。扩大包络后，故意过晚的迎面算例全候选被拒绝并停车，这是安全结果；折返仍能触发退让。近目标选中(0.075,0.075)m/s低速候选。最终保护的轴向/斜向限幅、雷达/命令/位姿失联停车，以及实体足印发布回归通过。

现场最终11×11+48低速候选配置，从A区停车点到门外12.292s，再从门外进入A区14.991s，均成功且无恢复；最小车中心到墙距离分别0.555/0.626m，峰值都约1.00m/s。完整数据见 `docs/doorway-evidence-20261003/summary.json`，实际轨迹见同目录 `doorway-routes.png`/`.svg`。这不代表整件抓放任务变快；其他门口尚未逐一验证，仿真仍为理想平面速度驱动。测试期间曾出现20Hz控制周期超时，不能宣称所有周期已稳定。
