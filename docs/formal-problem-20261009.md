# 正式题目输入与确认

依据本地《创新赛题目和映射规则.pdf》：出题程序使用比赛模式参数
`11470507`，题目每 30 分钟变化。省赛自行选择映射规则；国赛计时前由裁判选择。
题目和映射规则可以在计时前输入，核对后开始任务并计时。

当前代码支持文档展示的衣柜/书箱需求题型，包含同一需求、换种类、增减、倍数、
两人同需求。按题末明确的衣柜/书箱数量定义，合计各类需求，再按容量向上取整。
不支持的题型或不完整的定义报错，不能保证处理出题程序的所有潜在题型。
请用当天完整题目验证，并与裁判核对容量及向上取整的题意。

三条映射：

| 编号 | 颜色 | 区域 |
| --- | --- | --- |
| 1 | x 红、y 蓝 | 各自数量 >= 3 去 A，否则 C |
| 2 | 各自数量 >= 3 为红，否则蓝 | x 去 B、y 去 A |
| 3 | 较大值蓝、较小值红 | 蓝 B、红 C；相等时拒绝，需裁判明确 |

## 在 Foxglove 中使用

根目录 `demo1.json` 已配置正式题目发布、解题预览和确认启动三个面板。
重新导入此布局，保留 Rosbridge 连接，即可点击“解析正式题目”。默认内容是截图
种子 995245 的书箱示例和规则 1：x=1、y=4，任务为 1 红 C、4 蓝 A。
默认内容不是实时出题结果；正式比赛要替换为当时的题目。
布局文件修改不会自动改变客户端已打开的布局，需要重新导入。
JSON 嵌套、全部面板引用及默认题目映射已校验。

保持 Rosbridge 连接 `ws://127.0.0.1:8765`。发布面板（对话框）消息类型
`std_msgs/msg/String`，先将话题改为 `/competition/problem`。消息示例：

```json
{"data":"这里替换为完整正式题目，包括题末x、y的定义。\n映射规则：1"}
```

以上是模板，必须替换题目再发布。也支持在 data 内使用 JSON 字符串，字段
`problem` 和整数 `rule`；不必处理双层 JSON，通常直接用文字加规则编号即可。

新增原始消息面板查看 `/competition/preview`，可以看到人物需求、总需求、容量、
x、y、规则、搬运任务和 `preview_id`。此步骤不会发布 `/chat` 或启动搬运。
`/competition/status` 显示准备失败、等待确认、已启动等状态。

与裁判核对后，把发布面板话题改为 `/competition/start`，消息内容：

```json
{"data":"{\"preview_id\":\"替换为最新预览中的编号\",\"confirm\":true}"}
```

启动后按既有 `/chat` 接口执行任务；开始计时需要按裁判要求配合操作。
程序未新增自动计时器。旧 `/command` 仍立即解析普通搬运指令，不用于正式题目准备。

## 校验与验证范围

- 小模型直接求解衣柜示例曾输出错误答案 x=5、y=10。代码计算并核验正确结果
  x=4、y=1，再要求模型将对应搬运指令转为 JSON，与确定性映射比较。
  预览保留实际模型输出；不一致显示警告；模型服务失败则不生成可启动预览。
- 确认必须带最新编号和 `confirm=true`；重复确认不重复发任务。
- 新题目（包括解析失败）使旧预览失效；库存按同色任务累计校验。
- 主控每 0.5 仿真秒发布 `/competition/ready`；确认时必须收到五秒内的空闲状态。
  库存指主控尚未标为抓取的货物数量，并非新加入的视觉盘点。
- 13 项新测试和既有 12 项测试均通过；13 包构建完成。
- ROS_DOMAIN_ID=137 隔离验证了实际解析节点、模型请求、消息传输、预览不发任务和
  重复确认只发一次。测试域没有导航、Gazebo或机械臂，不控制当前机器人。
  实际模型映射与代码结果一致：4 红 A、1 蓝 C。
- 当前运行栈空闲日志确认后，只更新解析和主控节点。未发布真实搬运指令，未进行
  正式题目端到端搬运测试；当前场景的 C 区放置仍需要实测。
