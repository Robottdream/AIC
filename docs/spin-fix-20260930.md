本轮修改 `/mnt/e/workspace/AIC`，选择性同步到 `/home/polarbear/ws_aic`，使用一键脚本冷启动。尚未提交 Git。可选动态预测保持关闭。

## 结论与限制

新增保护已验证：Nav2 局部或全局代价地图所使用的机器人位姿超过 1 秒未更新时，最终速度输出的直行和旋转分量同时归零。原地旋转故障的底层原因尚未根治；不能将一次任务完成解释为导航通信稳定。

需要纠正此前“代价地图自身时钟冻结”的表述：Humble 的 Costmap2DROS::updateMap 将 getRobotPose 得到的 pose.header 复制到 published_footprint，getCurrentPose 使用 TF 转换得到位姿。因此本项目体检和探针测量的是 **TF 派生位姿时间戳的滞后**，不能据此判断节点自身 /clock 是否冻结。历史 JSON 字段、参数 require_costmap_clock 和工具文件名暂保留兼容性；提示及注释已修正。

源码依据：[Costmap2DROS](https://raw.githubusercontent.com/ros-navigation/navigation2/humble/nav2_costmap_2d/src/costmap_2d_ros.cpp)、[getCurrentPose](https://raw.githubusercontent.com/ros-navigation/navigation2/humble/nav2_util/src/robot_utils.cpp)。后续排障重点是 Nav2 内部 TF 消费与执行器更新。

用户原任务的完整速度轨迹未保留，日志曾被看门狗重启覆盖，不能断言该次原地转圈仅由一个原因引起。排障中确实复现了位姿时间戳过期、目标跨进程未送达以及规划接受超时。

## 改动

- scan_velocity_guard 增加局部/全局足迹消息的新鲜度检查，同时检查源时间戳和墙钟接收间隔，任一过期就输出零 Twist。原有雷达及命令失联保护保留。
- ROS 环境默认采用本机已安装的 Cyclone DDS，XML 限制环回发现、禁用组播，并使用 1400 B 消息上限、1200 B 分片。独立跨进程对照中，较大消息配置下完整 360 束雷达收不到，而 1 束雷达及 String 能收到；小包配置使四种消息全部通过，完整雷达观测约 9.94 Hz。该证据不等于证明内核或网络的具体故障原因，也未解决内部 TF 停更。
- 两路 Gazebo 激光发布改为 BEST_EFFORT、KEEP_LAST 深度 5，与现有传感器订阅匹配。
- 启动门显式指定消息类型；雷达使用 BEST_EFFORT，AMCL 使用 RELIABLE/TRANSIENT_LOCAL 接收静止时保留的位姿。等待门使用真实耗时，避免单次命令等待被漏算。
- 添加独立传输检查、位姿时间戳探针及两件任务计时选项。显式指定 RMW_IMPLEMENTATION=rmw_fastrtps_cpp 可做对照；手动 ROS 命令需在 ROS/install setup 后 source tools/ros_env.sh，与启动脚本保持一致。

测试期间 WSL 曾重新启动，不能把跨重启前后的全部差异归因于 DDS 配置。Cyclone 配置是当前本机可运行方案，不能声称长期通信故障已修复。
