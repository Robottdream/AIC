# 线/角加速20、横向/偏航1000：单轮流程尝试（2026-10-15）

## 实际设置与验证

按用户要求仅提高线加速度和角加速度，分别设20 m/s²和20 rad/s²；线减速度5 m/s²、角减速度10 rad/s²保持。线/角速上限8 m/s、4 rad/s；车体前向限力150 N、横向限力1000 N、偏航限矩1000 Nm，PI增益、摩擦1、ODE200/1ms保持。

控制器、规划器、平滑器、导航任务预测crossing_acceleration与场景生成器一致。隔离生成器输出nav/tasks与实际场景相同；任务前读回ROS参数与机器人URDF，确认20/20加速、5/10减速、8/4速度和150/1000/1000力矩。车轮fmax=0，旧轮子驱动未同时启用。此次没有修改转向控制算法或提高前向限力，指令加速度20不等于物理必达20。

## 为何仍未到8

上次3.5/5线加减速、10/10角加减速、同样1000/1000限额的尝试，实速峰值5.55、平滑后峰值5.60。本轮实速约6.53、平滑后6.80，采集到的目标仍未持续让平滑器输出到8，且流程只实际执行第一件两段主要导航。不同抓取方向、路线、障碍相位与任务长度，不是完全相同路径对照，不能用单轮差值推断稳定收益。

本轮前向限力仍150 N，机器人URDF总质量约14.51 kg，单看注入前向力的加速量级约10.3 m/s²，实际还叠加接触力、货物与姿态影响，不能把平滑器20当成车体实际20。角速度仍4、角制动10、线制动5；曲率、终点和预测刹停保护保留，墙距减速未恢复。三层线速图见speed-command-chain.png。

本次横向采样峰值约170 N，没有超过旧200 N限额的样本；偏航矩约136 Nm，有4个采样超过旧100 Nm，未触及1000上限。施力采样30Hz可能漏掉很短峰值，不当作逐物理步完整证明。横向速度与施力均按消息时间插值到车头坐标，含少量采样转换误差。

## 主要失败链路

共16次真实到达核验拒绝，日志距离范围约3.57至21.81 m。Nav2日志同时出现24次compute_path_to_pose目标确认超时，随后FollowPath很快输出Reached the goal和Goal succeeded，而机器人留在A区附近。

源码tools/continuous_navigation.xml的ForceSuccess允许规划失败时保留旧path，这原本用于运动中的滚动重规划；当前没有在新任务目标切换时限制该旧path的所属目标。结合超时后立即成功、物理位置距目标数米和源码，证据指向新目标规划失败后沿用已到达的旧路径。没有把此错误归因于扭矩不足、真实转向执行失败或角加速度20；本次未修改这条导航算法，也没有追加第二轮。

## 采集器修正与审阅

实际任务结束后，补充tools/benchmark_delivery.py对“没有可选的”终止文案的识别，增加terminal_failure_reason，保留既有终止条件。通过AST读取新常量与本轮真实错误行验证命中；no_path、放置连续失败等原分支匹配检查与Python编译通过。此次运行使用的原始采集脚本已快照；修正发生在运行落盘后，不篡改原始失败记录。分析器对失败轮次也按最终WAIT_TASK截断，另保留raw poll时间。

控制源码、二进制、xacro和运行工具在本轮执行结束、采集器修正前哈希一致；修正后的采集器与原快照哈希差异另记在harness-fix-validation.json。所有仿真进程已停止。
