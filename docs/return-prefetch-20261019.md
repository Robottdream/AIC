## 执行方式

导航节点在当前目标已受理、未紧急停止且Gazebo实测车体水平速度超过0.10 m/s时，对每个目标发布一次`moving`。主控仅在`NAV_TO_BLOCK`阶段发送`/return_prefetch_request`：6个浮点数为抓取点x/y/yaw和放置区x/y/yaw。重复的同一段运动消息不重复请求；空数组取消旧任务。

`aic_timed_planner`中的独立后台线程使用相同的0.20 m弧段SE2搜索，按静止的预期抓取姿态计算静态返程路线。后台有独立的搜索容器和启发场，不调用`/compute_path_to_pose`动作，不抢占当前BT规划请求。队列只保留最新请求，活动任务发现代际变化时退出；生命周期停止先取消并join线程，再释放资源。它会占用额外CPU，不能视为没有资源竞争。

缓存保留地图对象版本、请求代际、预期起点和目标、弧段节点、相对到达时间及生成时刻。它不存储旧移动障碍预测。前台正常`createPlan`仍是唯一返回执行路径的入口，只在目标位置/朝向匹配、起点距离≤0.20 m/角度≤0.35 rad、里程计≤0.20 s新鲜且测得低速≤0.10 m/s、缓存年龄≤30墙钟秒、地图/请求代际一致时尝试复用。

复核采用本次调用的新鲜定位与真实车身对齐、当前实际轮廓和移动障碍状态，从当前起点检查连接段及整条预计算路线。弧段内部检查步距≤约2 cm、角度步距≤0.05 rad，并重新设置相对时间起点；不会沿用旧动态预测。检查期间地图/代际改变、状态不新鲜、碰撞或其他条件不符时，回到现有动态搜索。5 Hz滚动规划和20 Hz预测控制保护保留。选块后的导航预查仍存在，预计算可能被预查和BT起步分别复核，尚未删除重复预查。

任务/抓取方向改变、地图变化、抓取重试、放置纠偏、区域导航失败、停止和完成会取消旧结果。抓取成功消息到来后，主控才发出放置导航目标；后台计算本身不会发导航指令。

## 观察与开关

`main_controller_node.return_prefetch_enabled`默认true，设false可停用请求（下一次启动参数生效）。`/return_prefetch_status`记录queued/ready/discarded/failed/reused/rejected、代际、仿真时刻和部分操作墙钟耗时。`tools/record_navigation.py`保存`observed/return-prefetch.json`。ready只表示静态预计算完成；reused才表示该次前台复核通过；同一准备路线可被预查和BT分别使用，事件条数不等于独立返程条数。
