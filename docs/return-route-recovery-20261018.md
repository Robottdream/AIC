# 返程无路时恢复过快的修复（2026-10-18）

前一轮单次通过后，用户重新冷启动，仍出现最后一件未放置。
最后持有 `blue_cube_5`，机器人停在约 (-4.047, -5.665)，目标 A (-7.95, -5.56)。
没有出现旧终点到达误报；停车定位恢复实际执行且核验通过，但随后的新导航均规划无路。

日志墙钟时间戳：第一次返回中止 1792305121.796，停车定位通过 1792305122.891；
随后中止 1792305123.394，第二次定位通过 1792305123.505；
最终 1792305123.997 中止并触发主控终止。恢复在约两秒内耗尽。
同一个停车位置的后续五次真实路径查询都成功返回 29 个路径点。
这证明失败时的“无路”不能直接当作永久不可达；定位一致本身也不足以证明现在能够重启导航。
原始日志同时存在定位/TF 异常，尚未完全隔离全部首次规划失败的成因。

## 修改

延续当前目标严格初次规划和停车定位恢复，增加以下门槛：

- 停车定位核验通过后，异步查询**当前目标**路径；没有有效路径时继续停车查询，
  不立即发送 NavigateToPose，也不消耗另一次导航恢复次数。
- 同时最多一个路径查询；失败后至少间隔 0.75 秒再次查询。
- 路径必须为 map 坐标系、非空、终点距当前任务目标小于 5 cm，且结果在 0.5 秒内。
  通过后再交给 Nav2，Nav2 仍须重新规划并执行原有实时轮廓检查。
- 每次恢复原有十秒墙钟上限和两次恢复上限保持；即使定位和路径有效，超时也不能重启。
- 超时、急停、新目标时取消未完成查询；迟到接受的规划请求也取消，避免启动旧任务。

没有改地图、轨道、速度/加减速度、驱动或碰撞保护，也没有向 AMCL 注入真值。
这是对已证实恢复缺口的修复，不声称消除了所有 TF 丢帧和全局搜索失败。
